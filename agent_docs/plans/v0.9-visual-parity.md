# Plan: ferritex v0.9 — Visual parity batch

## Status

IN PROGRESS (2026-02-24): implementation + tests + docs updates are done; remaining steps are commit/PR and optional manual visual validation on an external corpus.

## Context

PR #23 (v0.8 TOC parity) is merged. This plan covers the next batch of visual parity
issues found by manual inspection of `dissertation.docx` vs `*_manual.docx` / PDF reference.

Branch: `feat/v0.9-visual-parity` (new, from master after rebasing).

**Issues in scope (priority order):**

1. **List indent** — continuation lines of list items shift left. LaTeX uses `nosep` +
   `leftmargin=\parindent-\labelwidth-\labelsep` + `itemindent=\labelwidth+\labelsep`,
   meaning both first line and continuation lines align at `\parindent`. DOCX currently
   uses `list_left_indent_twips=600` and `hanging=240`, which is wrong.
2. **Source lines** (`\figuresource`/`\tablesource`) — wrong: justified, body font size.
   LaTeX: `{\noindent\raggedright\small\textit{#1}}`, table source has 4pt vspace above,
   figure source has 2pt. Must be: Left-aligned, small italic, no indent.
3. **Caption indent** — currently inherits `caption_indent_twips` which may add left offset.
   LaTeX: no indent for figure captions (`format=plain`, no indent field). Verify and fix.
4. **List bullet** — LaTeX uses `\labelitemi{\normalfont\bfseries{--}}` (bold en-dash),
   ferritex uses `•`. Must extract and use correct label character.
5. **Title page page suppression** — `\thispagestyle{empty}` in title.tex → page number
   on first page must be suppressed. Currently page number appears.
6. **Bibliography** — `\printbibliography` and `\insertbibliofullsorted` not rendered at all.
   Must render as a heading + list of `\bibitem`-style entries from `.bib` file or at
   minimum emit a placeholder heading "СПИСОК ЛИТЕРАТУРЫ".

**Out of scope for v0.9 (deferred):**
- Math OOXML oMath (requires `docx-rs` raw XML injection, large effort)
- Citation "Там же." deduplication (requires runtime state tracking, complex)
- Internal hyperlinks / TOC hyperlinks (requires DOCX bookmark infrastructure)
- Appendix letter numbering (deferred)

## Task 1 — Fix list indent geometry

### Rationale

LaTeX enumitem geometry with `leftmargin=\parindent-\labelwidth-\labelsep`,
`itemindent=\labelwidth+\labelsep` produces: first-line text starts at `\parindent` from
margin, continuation lines also start at `\parindent` from margin (no hanging effect
visible to the reader). In DOCX terms: `w:ind w:left` = `\parindent`, `w:hanging` = 0
(or equivalently, both `left` and `firstLine` cancel each other to put text at parindent).

Correct DOCX geometry for these enumitem settings:
- `w:ind left` = `body_first_line_indent_twips` (= parindent, e.g. 709 twips = 1.25cm)
- `w:ind hanging` = 0 (no hanging)
- The numbered/bulleted label appears via `w:numPr` in the paragraph

Actually, a cleaner DOCX approach that matches this LaTeX model:
- Abstract numbering level: `left` = `body_first_line_indent_twips`, `hanging` = some
  reasonable label width (so label is at `left - hanging`, text at `left`)
- The label hangs into the `hanging` space, continuation lines wrap at `left`

Given `labelsep=0.5em ≈ 142 twips` and typical `labelwidth ≈ 0.5em` for a bullet/dash:
- `left` = parindent = 709 twips
- `hanging` = labelsep + labelwidth ≈ 284 twips (so label starts at 709-284=425 twips)

However, to keep this **generic and LaTeX-driven**, ferritex should:
1. Add new `DocumentLayout` fields: `list_label_sep_twips: Option<i32>` and
   `list_label_width_twips: Option<i32>`.
2. Extract from `\setlist{labelsep=.5em, labelwidth=!}` — for `labelwidth=!` (auto),
   treat as equal to `labelsep`. Convert em to twips: 1em ≈ font_size_body_hp/2 * 20.
3. In renderer: compute `list_left` = `body_first_line_indent_twips`,
   `list_hanging` = `list_label_sep_twips + list_label_width_twips`.
   Fallback: `list_left` = 709, `list_hanging` = 284.

### 1.1 New fields in `src/model/mod.rs`

Add after `list_hanging_indent_twips`:

```rust
/// Label separator in twips (from \setlist{labelsep=...}).
pub list_label_sep_twips: Option<i32>,
/// Label width in twips (from \setlist{labelwidth=...}; None if "!"/auto).
pub list_label_width_twips: Option<i32>,
/// Bullet character for \labelitemi (e.g. "–" for bold en-dash).
pub list_bullet_char: Option<String>,
```

### 1.2 New constants in `src/renderer/docx.rs`

```rust
/// Default list left indent = body first-line indent (1.25cm = 709 twips).
const DEFAULT_LIST_LEFT_TWIPS: i32 = 709;
/// Default list hanging indent = labelsep + labelwidth ≈ 2 × 0.5em at 14pt ≈ 284 twips.
const DEFAULT_LIST_HANGING_TWIPS: i32 = 284;
/// Default bullet character.
const DEFAULT_LIST_BULLET: &str = "•";
```

Replace existing `LIST_LEVEL_LEFT_INDENT_TWIPS = 600` and `LIST_LEVEL_HANGING_TWIPS = 240`
with the new constants above (or keep old as internal fallback and add new ones — but update
the `register_numbering()` and `build_list_item()` calls to use correct values).

### 1.3 New fields in `RenderProfile`

```rust
list_bullet_char: String,
```
(List geometry already in `list_left_indent_twips` / `list_hanging_indent_twips` — just
fix the default values and `from_layout()` computation.)

### 1.4 `from_layout()` changes

```rust
// Compute list left = body indent (parindent equivalent)
list_left_indent_twips: layout.list_left_indent_twips
    .unwrap_or_else(|| layout.body_first_line_indent_twips.unwrap_or(DEFAULT_LIST_LEFT_TWIPS)),
// Compute list hanging = labelsep + labelwidth
list_hanging_indent_twips: {
    let sep = layout.list_label_sep_twips.unwrap_or(142); // 0.5em at 14pt
    let width = layout.list_label_width_twips.unwrap_or(sep); // auto = labelsep
    layout.list_hanging_indent_twips.unwrap_or(sep + width)
},
list_bullet_char: layout.list_bullet_char.clone()
    .unwrap_or_else(|| DEFAULT_LIST_BULLET.to_string()),
```

### 1.5 `register_numbering()` changes

Change bullet text from hardcoded `"•"` to `profile.list_bullet_char.as_str()`.

### 1.6 New extraction function in `src/parser/latex.rs`

`fn extract_list_settings(source: &str) -> (Option<i32>, Option<i32>, Option<String>)`

- Find `\setlist{...}` block (possibly multiline, balance braces)
- Extract `labelsep=<dim>` → convert to twips (handle `em`, `pt`, `cm`, `mm`)
- Extract `labelwidth=!` → `None` (auto), `labelwidth=<dim>` → Some(twips)
- Extract `\renewcommand{\labelitemi}{...}` → strip `\normalfont\bfseries` → keep the char
  (e.g. `{--}` → `"–"`, `{\textendash}` → `"–"`)
- Return `(label_sep_twips, label_width_twips, bullet_char)`

Call site in `extract_layout_settings()`:

```rust
let (label_sep, label_width, bullet) = extract_list_settings(source);
layout.list_label_sep_twips = label_sep;
layout.list_label_width_twips = label_width;
layout.list_bullet_char = bullet;
// Override list_left to = body_first_line_indent when set
if layout.list_left_indent_twips.is_none() {
    layout.list_left_indent_twips = layout.body_first_line_indent_twips;
}
```

## Task 2 — Fix source line (`\figuresource`/`\tablesource`) rendering

### Rationale

LaTeX definition:
```latex
\tablesource: \par\vspace{4pt}{\noindent\raggedright\small\textit{#1}\par}
\figuresource: \par\vspace{2pt}{\noindent\raggedright\small\textit{#1}\par}
```

Must be: left-aligned, small font (footnote size), italic, no indent, with vspace before.

### 2.1 New `DocumentLayout` fields

```rust
/// Vertical space above table source line in twips (from \tablesource vspace).
pub source_vspace_table_twips: Option<i32>,
/// Vertical space above figure source line in twips (from \figuresource vspace).
pub source_vspace_figure_twips: Option<i32>,
```

Default: `4pt → 80 twips` for table, `2pt → 40 twips` for figure.

### 2.2 New constants in `src/renderer/docx.rs`

```rust
const DEFAULT_SOURCE_VSPACE_TABLE_TWIPS: i32 = 80;  // 4pt
const DEFAULT_SOURCE_VSPACE_FIGURE_TWIPS: i32 = 40; // 2pt
```

### 2.3 New `RenderProfile` fields

```rust
source_vspace_table_twips: i32,
source_vspace_figure_twips: i32,
```

### 2.4 `source_paragraph()` changes

Change from:
```rust
.align(AlignmentType::Both)
```
To:
```rust
.align(AlignmentType::Left)
```

Apply italic to all runs. Use `font_size_footnote_hp` for the size (already done via
`inline_runs_with_footnote_size`). Add `space_before` from `source_vspace_*_twips`.

`source_paragraph()` needs a context parameter: `vspace_twips: i32`. Add `Paragraph::space_before(vspace_twips)`.

Then pass the correct vspace depending on context (figure vs table):
- After table: `profile.source_vspace_table_twips`
- After figure: `profile.source_vspace_figure_twips`

The `Block::Source` in the AST doesn't currently distinguish table vs figure context.
**Simple approach**: add `source_kind: SourceKind` to `Block::Source` (or use a boolean `is_figure`).

Actually checking model: `Figure.source: Vec<Inline>` and `Table.source: Vec<Inline>` exist
separately. In renderer they're called separately. So pass the correct vspace at call site.

### 2.5 Parser extraction

`fn extract_source_vspace(source: &str, macro_name: &str) -> Option<i32>`
- Find `\newcommand{\<macro_name>}[1]{` ... `\vspace{<dim>}` ...
- Convert `<dim>` to twips
- Return `Some(twips)`

Call in `extract_layout_settings()`:
```rust
layout.source_vspace_table_twips = extract_source_vspace(source, "tablesource");
layout.source_vspace_figure_twips = extract_source_vspace(source, "figuresource");
```

## Task 4 — Bibliography placeholder rendering

### Rationale

`\printbibliography`, `\insertbibliofullsorted`, `\insertbiblioauthor` are not rendered at all.
The bibliography section is completely missing from the DOCX output.

**Minimum viable approach** (sufficient for v0.9):
- Parse `\printbibliography` and `\insertbibliofullsorted` as `Block::BibliographyPlaceholder`
- Render as a chapter-level heading "СПИСОК ЛИТЕРАТУРЫ" (or extract title from LaTeX option `[title=...]`)
- No `.bib` file parsing — emit heading only with a note "(bibliography not rendered)"

**Better approach** (if feasible): Also parse `\bibitem` entries from `.bib` files. This
is complex and out of scope for v0.9. Stick with minimum viable.

### 4.1 New model variant

In `src/model/mod.rs`, add to `Block` enum:

```rust
/// Placeholder for a bibliography section (rendered as heading).
BibliographyHeading { title: String },
```

### 4.2 Parser changes

In `src/parser/latex.rs`, detect:
- `\printbibliography` → optional `[title=...]` argument
- `\insertbibliofullsorted` → default title "СПИСОК ЛИТЕРАТУРЫ"
- `\insertbiblioauthor` → same

Extract title from optional argument or fallback to "СПИСОК ЛИТЕРАТУРЫ".

Emit `Block::BibliographyHeading { title }`.

### 4.3 Renderer changes

In `src/renderer/docx.rs`, handle `Block::BibliographyHeading`:
- Render as `Paragraph` with style `"Heading1"` (same as `\chapter*{}`)
- Apply `heading_uppercase` if set in profile
- No page break before (bibliography follows conclusion)

## Task 5 — Title page: suppress page number

### Rationale

`\thispagestyle{empty}` in title.tex → title page should have no page number.
Currently ferritex always adds a footer with page number starting at page 1.

**Investigation needed**: How does ferritex currently emit page numbers? Check if there's
a section break / different first-page header setting in the DOCX section properties.

**Approach**:
- Add `DocumentLayout` field: `title_page_suppress_number: Option<bool>`
- Extract `\thispagestyle{empty}` near `\begin{titlingpage}` or at document start
- In renderer: set `SectionProperty` with `titlePg` flag (different first page header/footer)
  and leave first-page footer empty

**DOCX mechanism**: `<w:titlePg/>` in `<w:sectPr>` enables "different first page" header/footer.
With `<w:titlePg/>`, the first page uses footer `type="first"` (empty) while subsequent pages
use footer `type="default"` (with page numbers).

### 5.1 New `DocumentLayout` field

```rust
/// Whether to suppress page number on the first (title) page.
pub title_page_suppress_number: Option<bool>,
```

### 5.2 Parser extraction

`fn extract_title_page_suppress(source: &str) -> Option<bool>`
- If `\thispagestyle{empty}` found near `\begin{titlingpage}` or `\begin{titlepage}`,
  return `Some(true)`

### 5.3 Renderer changes

In `build_section_properties()` or wherever `SectionProperty` is built:
- If `profile.title_page_suppress_number == true`, add `<w:titlePg/>` and add an empty
  first-page footer element
