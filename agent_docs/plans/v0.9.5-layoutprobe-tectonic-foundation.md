# Plan: v0.9.5 LayoutProbe (embedded tectonic) Foundation

## Status

PLANNED (created 2026-02-25).

## Goal

Maximize cross-project LaTeX compatibility by reducing renderer fallbacks to true edge cases.
Primary strategy:

```text
LaTeX source -> LayoutProbe (engine-evaluated effective values) + parser static extraction
             -> merge (probe > parser > fallback)
             -> AST + DocumentLayout
             -> RenderProfile::from_layout()
             -> renderer
```

This plan is the foundation for broad real-world LaTeX support and must precede deep PDF/MD backend expansion.

## Dependency Policy (approved candidates)

Primary candidate:
- `tectonic` `0.15.0` (MIT): embedded TeX/LaTeX engine for effective layout/style probing.

Optional supporting candidates:
- `codebook-tree-sitter-latex` `0.6.1` (MIT): syntax indexing only (not semantic evaluation).
- `biblatex` `0.11.0` (MIT/Apache-2.0): bibliography parsing/evaluation support.

Not allowed for MIT core integration:
- `tex_engine` `0.1.8` (GPL-3.0-or-later),
- `rustex_lib` `0.1.7` (GPL-3.0-or-later).

## Non-negotiable constraints

1. No corpus-specific hardcodes.
2. No external LaTeX subprocess orchestration in runtime path for probe extraction.
3. Probe results must be normalized into generic `DocumentLayout` fields.
4. Renderer defaults remain fallback-only.

## Implementation Workstreams

### 1) Core probe contract in `ferritex-core`

- Introduce `LayoutProbeOutput` (internal normalized probe schema).
- Define deterministic merge contract into `DocumentLayout`:
  - probe value wins when present,
  - parser static extraction fills missing fields,
  - renderer fallback only when both are absent.
- Keep merge idempotent and side-effect free.

### 2) Embedded `tectonic` spike (minimal vertical slice)

- Integrate `tectonic` as optional feature-gated dependency in `ferritex-core`.
- Build minimal probe pipeline for high-impact fields first:
  - body font size/family,
  - paragraph indent,
  - line spacing,
  - list geometry (`labelsep`, `labelwidth`, `leftmargin`, `itemindent`, `listparindent`),
  - page margins / paper size / gutter.
- Capture probe outputs in a sidecar-like structure consumable by parser/model code.

### 3) Parser/probe merge wiring

- Add merge step before final `Document` return in parse entrypoints.
- Ensure no behavior regression when probe is disabled/unavailable.
- Preserve existing parser behavior as deterministic fallback path.

### 4) Bibliography and syntax helpers (optional stream)

- Evaluate `biblatex` integration for bibliography semantic gaps.
- Evaluate `codebook-tree-sitter-latex` where syntactic disambiguation improves extraction reliability.
- Add only if measurable extraction signal improves and complexity remains bounded.

### 5) Test strategy for probe integration

- Unit tests:
  - probe output normalization,
  - merge precedence (`probe > parser > fallback`),
  - absent-probe deterministic fallback behavior.
- Integration tests:
  - representative multi-file fixtures,
  - regression checks for previously fixed DOCX parity issues.
- Property-based tests (aligned with v0.9.4):
  - merge determinism,
  - monotonic length conversion invariants,
  - no-panics under partial probe/parser data.

## Deliverables

1. `ferritex-core` probe contract + merge implementation (feature-gated initial version).
2. Initial `tectonic`-backed extraction for selected high-impact fields.
3. Updated docs:
   - `AGENTS.md`,
   - `agent_docs/latex_driven_policy.md`,
   - `docs/ARCHITECTURE.md`,
   - `docs/ROADMAP.md`,
   - `docs/SUPPORTED_ELEMENTS.md`.
4. Test coverage proving precedence and fallback minimization.

## Exit Criteria

1. Probe integration works on representative LaTeX projects without external LaTeX subprocess orchestration.
2. For covered fields, renderer fallback usage is demonstrably reduced.
3. No regressions in workspace quality gate.
4. Documentation and session memory are synchronized to the new architecture.
