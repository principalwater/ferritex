# Plan: v1.0 Multi-Backend Foundation

## Status

IN PROGRESS (started 2026-02-24), with DOCX parity stabilization tracked separately in:
- `v0.9.1-docx-manual-qa-followup.md` (baseline wave),
- `v0.9.3-docx-parity-disstyles-wave2.md` (current active wave).

## Context

Workspace has been refactored to crate-per-layer / crate-per-backend:
- `ferritex-core` (parser + model)
- `ferritex-renderer-docx` (implemented)
- `ferritex-renderer-pdf` (canonical `latex_to_pdf` baseline implemented)
- `ferritex-renderer-md` (stub)
- root crate orchestrates CLI/TUI/build dispatch.

Integration tests are now split by output format and reuse shared fixtures.

Current sequencing constraint:
- Before deep PDF/MD implementation, active DOCX manual-QA parity WIP must be stabilized
  (compiling tree, passing tests, and finalized parser/model/renderer mapping for current defects).
- Before deep PDF/MD implementation, LayoutProbe foundation must reach a usable baseline:
  - `v0.9.5-layoutprobe-tectonic-foundation.md`
  - probe-parser merge contract in place (`probe > parser > fallback`) for core layout fields.
- Test-system modernization is tracked in `v0.9.4-test-organization-and-property-based.md`
  and should run in parallel, because backend expansion depends on scalable test architecture.

## Goals

1. Keep AST + `DocumentLayout` as a single source-of-truth contract for all backends.
2. Implement canonical PDF path via `tectonic::latex_to_pdf` for 1:1 visual parity workflows.
3. Keep DOCX/MD backends on parser-first + probe-fallback semantic contract.
4. Keep tests maintainable as backend count grows.

## Work Items

1. PDF backend implementation (`crates/ferritex-renderer-pdf` + build orchestration):
   - ✅ canonical `tectonic::latex_to_pdf` execution path for parity mode wired,
   - ✅ artifact/output contract for PDF build pipeline defined in build core + renderer wiring,
   - ✅ integration test added for deterministic PDF artifact generation (`tests/integration_pdf.rs`),
   - keep documenting boundaries between canonical PDF path and AST/StyleMap semantic path as backend semantics expand.

2. Markdown backend implementation (`crates/ferritex-renderer-md`):
   - define deterministic block/inline mapping rules,
   - implement `render_md_with_context`,
   - add renderer unit tests,
   - add integration tests with fixture-based expected `.md` artifacts.

3. Build/CLI completion:
   - ensure `build --format pdf|md|all` behavior is validated end-to-end,
   - keep artifact naming/path resolution unified in `src/build`.

4. Documentation alignment:
   - keep `AGENTS.md`, `docs/ARCHITECTURE.md`, `agent_docs/*` consistent with workspace flow,
   - update `docs/SUPPORTED_ELEMENTS.md` as each backend reaches feature parity milestones.

5. Dependency sync with active DOCX parity plan:
   - reuse parser/model semantics from `v0.9.1-docx-manual-qa-followup.md`,
   - reuse probe/merge semantics from `v0.9.5-layoutprobe-tectonic-foundation.md`,
   - avoid backend divergence by extending shared AST/`DocumentLayout` first.
